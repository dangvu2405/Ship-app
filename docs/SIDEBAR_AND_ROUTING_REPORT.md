# Báo Cáo Thay Đổi Sidebar & Router Configuration

**Ngày tạo:** `2026-05-13`  
**Mục đích:** Document lại việc gỡ bỏ các flag phân quyền local trên UI tại `AppSidebar.tsx` và chuẩn hóa hiển thị router.

## 1. Vấn đề giải quyết

- Trước đây, `AppSidebar.tsx` sử dụng các biến boolean hardcode (`isAdmin`, `hasAccounting`, `canViewUsers`, v.v.) để render điều kiện các mục trong menu. Điều này làm rối code, không an toàn và che giấu các component router mà đáng lẽ Refine/react-router cần handle việc access control thông qua `authProvider`.
- Việc render điều kiện bằng toán tử spread `...(condition ? [...] : [])` trong `useMemo` gây khó đọc và giảm performance không đáng có.

## 2. Giải pháp đã áp dụng

- **Xóa các cờ Permission ở Frontend Sidebar:** Xóa bỏ toàn bộ các biến mock permission. Sidebar hiện tại sẽ render 100% các menu path đang có cấu hình router thực tế trong hệ thống.
- **Clean Code `useMemo` Dependency:** Xóa các biến hardcode thừa thãi khỏi mảng dependency của `useMemo` trong `AppSidebar`.
- **Tính chính xác của Routing:** Mọi leaf route (ví dụ `ROUTES.admin.accounting.revenue`, `ROUTES.admin.settings.users`) được đối chiếu chéo (cross-checked) với khai báo router provider và object config trong codebase. Đảm bảo toàn bộ menu dẫn đến các URL thật, không bị văng lỗi màn hình "404 Not Found".

## 3. Lưu ý cho người tiếp nhận (Next Developers)

- **Phân Quyền (RBAC):** Kể từ nay, việc user có được phép truy cập vào router hay không sẽ hoàn toàn phụ thuộc vào `RequiredRole` Component, Route Guards, hoặc quyền giới hạn data ở BE (`user_permissions`). Không đặt logic chặn/ẩn menu thủ công tại Sidebar để tránh mismatch trạng thái giữa Router và UI.
- **Router Keys:** Nếu tạo thêm trang mới, hãy chắc chắn đã đăng ký trong file cấu hình Router (`routes/appRouteConfig.tsx` hoặc tương đương trong hệ thống alias của Refine) trước khi nhúng path vào hàm `leaf()` trong `AppSidebar.tsx`.

## 5. Cập nhật đồng bộ Routing giữa AppSidebar và AppRouteConfig

**Vấn đề:**
Sidebar chứa một số menu dẫn đến path bị sai (hoặc không tồn tại trong `appRouteConfig.tsx`), dẫn đến việc truy cập key của Object là `undefined`. Điều này khiến Router không match được component và tự động redirect (fallback) về trang `/dashboard`.

**Hành động đã thực hiện:**
Cross-check `AppSidebar.tsx` với file `appRouteConfig.tsx` (danh sách `crudRoutes` và `singleRoutes`) để fix chính xác các property path:

- Sửa `vehicleAssignments` -> `vehicle_assignments.list`.
- Sửa `vehicleExpenses` -> `vehicle_expenses.list`.
- Sửa `tripBonusRules` -> `trip_bonus_rules.list`.
- Sửa cấu trúc `payroll`: `payrolls.list`, `payroll_adjustments.list`, `allowances.list`, `deductions.list`.
- Xóa các menu ảo chưa được mount trong `appRouteConfig.tsx`: "Bảo dưỡng xe", "Chuyến chờ phân công", "Bảng giá khách hàng".
- Cập nhật nhóm Setting: liên kết chuẩn tới `settings.root`, `users.list` và `systemUsers`.
